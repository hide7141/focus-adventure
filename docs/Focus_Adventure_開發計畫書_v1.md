# Focus Adventure 開發計畫書 v1.0

> 專案定位：兒童注意力與自我管理訓練平臺  
> 使用情境：家庭私用為主  
> 核心目標：協助孩子練習注意力、自我控制、等待、任務完成、情緒調節與生活結構，並讓家長透過長期資料了解哪些方法對孩子較有效。  
> 重要界線：本系統不是 ADHD 診斷工具，也不取代醫師、治療師、學校與其他正式支持。

---

## 1. 專案背景與開發原因

本專案源自家庭日常需求。孩子目前有活動量高、容易分心、等待困難、衝動控制較弱、情緒與睡眠困擾、做事情需要較多提醒等情形。除了依循正式醫療與專業評估管道外，希望建立一套可融入家庭生活、能短時間使用、能長期持續、能量化觀察的自我管理訓練系統。

系統不以「治療 ADHD」為產品定位，而聚焦於：

- 注意力練習
- 自我控制與等待
- 任務啟動與完成
- 減少對家長提醒的依賴
- 情緒調節
- 日常生活結構建立
- 目標設定與延遲滿足
- 家長觀察與長期趨勢整理

系統應利用孩子對互動科技的興趣，但刻意避免設計成高黏著、無限遊玩型 3C 產品。

---

## 2. 產品核心概念

Focus Adventure 採「短時數位訓練 + 整日生活任務 + 家長確認 + 長期分析」雙軌模式。

### 2.1 短時數位訓練
平日以約 10～20 分鐘為平均使用區間，可依體力與當日狀況彈性調整。

內容可包含：
- 注意力遊戲
- 抑制控制遊戲
- 工作記憶遊戲
- 等待訓練
- 互動故事
- 情境題
- 未來加入相機動作辨識、Exergaming、AR 等

### 2.2 整日生活任務
將家庭生活中的真實行為轉成任務：
- 整理書包
- 刷牙
- 洗澡
- 收玩具
- 寫功課
- 睡前流程
- 等待
- 自己開始做事情
- 遵守約定
- 其他可由家長新增的家庭任務

### 2.3 核心閉迴路
任務 → 孩子執行 → 孩子自評 → 家長確認 → 點數/進度 → 情境紀錄 → 分析 → 調整下一輪任務。

## 3. 系統使用者與角色

### 3.1 孩子端
負責：
- 查看今天要做什麼
- 執行生活任務
- 進行短時訓練
- 自我回顧
- 累積星星與成長進度
- 選擇心願目標

### 3.2 家長端
負責：
- 建立與調整任務
- 確認孩子完成狀況
- 設定獎勵
- 記錄少量必要情境
- 查看趨勢
- 管理心願
- 匯出可與老師、醫療專業人員溝通的家庭觀察摘要

### 3.3 老師與醫療專業人員
不是系統角色，不需帳號、不登入系統。
系統僅提供家長：
- 學校回饋輸入
- 聯絡簿觀察整理
- 專業溝通摘要
- PDF/列印資料

## 8. 點數與獎勵機制

### 8.1 三層獎勵
1. 立即回饋：星星/點數
2. 成長與解鎖：等級、勳章、地圖、挑戰
3. 現實心願：由家長建立的心願商店

### 8.2 核心原則
- 以加分為主，不以扣分為主
- 完成任務有基本點數
- 自主完成可有 Bonus
- 被提醒不取消基本完成
- 家長確認後才計入正式星星
- 盡量避免事後把孩子已認為取得的點數扣回

### 8.3 心願商店
可由家長自由新增：
- 零用金
- 玩具
- 想去的地方
- 特別活動
- 額外娛樂時間
- 中長期心願
- 其他自訂

系統不限制心願種類與規模。

## 9. 孩子閱讀能力與操作設計

目前孩子剛上小一，尚未完全具備獨立閱讀能力，因此孩子端必須採：

**Visual-first + Audio-first**

優先順序：
1. 圖示/圖片
2. 語音
3. 極短文字
4. 可選注音

任務卡應支援：
- 自動語音
- 點擊重播
- 大按鈕
- 一次只顯示目前步驟
- 不依賴閱讀才能操作

# 10. UI Design System v1

## 10.1 孩子端設計原則

### 操作原則
- 每頁主要決策最多 1 個
- 次要選項最多 2～4 個
- 一次只顯示目前任務重點
- 不使用無限捲動
- 不使用排名
- 不自動進下一關
- 不以「失敗」紅字刺激孩子
- 任務未完成可「稍後再試」
- 動畫短、明確，不以刺激黏著為目的

### 版面
- 主要操作按鈕高度：56～72 px
- 主要任務卡：手機畫面約 40～45%
- 觸控目標需足夠大
- 大圖示 + 大標題
- 一頁只強調一個主任務

### 字體建議
- 主標題：28～32 px
- 任務名稱：24～28 px
- 主要按鈕：20～24 px
- 說明文字：18～20 px
- 避免小於 16 px

### 導航
孩子端底部 4 項：
- 今日
- 挑戰
- 成長
- 日曆

### 色彩原則
- 明亮、溫和、高可辨識
- 不使用過度閃爍
- 紅色只用於警示，不用於「你失敗」
- 主任務與完成狀態需清楚區分

### 動畫
- 一般回饋：0.5～1 秒
- 不做抽卡轉盤
- 不做 Loot Box
- 不做長時間煙火
- 不做「再玩一局？」誘導

---

## 10.2 家長端設計原則

目標：30 秒內了解今天發生什麼。

### 首頁資訊層級
1. 今日任務
2. 待確認
3. 今日值得注意
4. 本週趨勢

### 操作
- 任務確認每項 1～2 秒
- 避免每次跳「確定嗎？」
- 可復原
- Context Tag 採第二層選填
- 批次處理優先

### 家長底部導航
- 今日
- 確認
- 任務
- 分析
- 更多

## 10.3 Responsive Design

### 手機
- 單欄
- 主任務置頂
- 大按鈕

### 平板橫式
- 左：現在任務
- 右：今日資訊/心願

### 電視

不使用「失敗原因」，改稱「當時狀況」。

建議預設標籤：
- 忘記開始
- 做到一半分心
- 不太想開始
- 情緒影響
- 疲累
- 不清楚怎麼做
- 不確定

## 18. 3C 使用與防沉迷設計

系統不靠刪功能解決沉迷，而採結構化限制：

- 每日最多挑戰次數
- 每日時間預算
- 任務時段限制
- 不做無限關卡
- 不做連續自動播放
- 不做抽卡
- 不做每日登入壓力
- 不做 Streak 歸零懲罰
- 完成後把孩子送回現實任務

可由家長設定：
- 平日分鐘數
- 假日分鐘數
- 每日關卡數
- 可提前解鎖
- 可延後解鎖
- 可暫停關卡

## 20. MVP 成功標準

第一版不以功能數量為成功標準。

建議先觀察：
- 孩子是否願意連續使用 2～4 週
- 孩子是否能在不大量依賴家長讀文字下操作
- 家長每日確認時間是否可控制在數分鐘內
- 任務資料是否能產生可理解趨勢
- 是否開始看出「自主完成」「提醒需求」等變化
- 系統是否能把螢幕活動導回真實生活

若上述成立，再擴充 AI、動作辨識、AR。

## 21. 目前正式凍結的核心產品決策

1. 私用家庭系統，不設老師端、醫療端。
2. 孩子端與家長端是兩套不同 UI。
3. 孩子端 Visual-first + Audio-first。
4. Task Engine 是核心，不是遊戲本身。
5. Progression 與 Difficulty 分離。
6. Pending Points 與 Confirmed Points 分離。
7. 以加分與 Bonus 為主，不以扣分為主。
8. 心願商店同時承擔延遲滿足與目標管理。
9. Context Tag 記錄「當時狀況」，不宣稱原因。
10. 成功條件與未完成情境同等重要。
11. 報告只作家庭觀察與溝通，不作診斷。
12. AI 生成內容需家長審核。
13. 3C 採時間/次數/時段管理，不靠刪除有用功能。
14. AR/VR 為後續擴充，不是第一階段必要條件。
